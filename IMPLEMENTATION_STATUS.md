# FitProgressAI 2.0 Ultimate — состояние реализации

Дата: 2026-11-01. **Версия `2.0-dev`, частичная модернизация; полная Ultimate не завершена.** Существующий проект/архитектура и история Git сохранены.

## Проверяемый результат сессии

- Новый debug APK создан в `app/build/outputs/apk/debug/app-debug.apk`, versionCode 2, `2.0-dev`.
- APK собран SDK-инструментами с уже имевшимися Gradle intermediates: Kotlin/Compose → javac Room v1 → D8 → AAPT2 → zipalign → apksigner. Подпись/выравнивание проверены. Размер/hash — `docs/verification/v2/apk.json`.
- **Стандартный Gradle build и Lint не пройдены**: read-only wrapper lock, а с writable home — запрещённый daemon socket.
- **58 JVM-тестов пройдены**. 6 Room/совместимость и 4 Compose UI-теста компилируются, **не исполнялись**.
- Установка, launch и работа на физическом Android не проверены: ADB socket запрещён. P0 нельзя считать полностью принятым до smoke-теста.

## Аудит и исправления P0

Подробности — `docs/AUDIT_V2.md`. На старте был существующий APK 1.0 и полный кэш зависимостей, хотя старый статус говорил обратное. Исходный APK зафиксирован по SHA-256. Проверены Gradle, manifest, Room, таймеры, GPS, Compose, repository и навигация.

Исправлены wall-clock таймеры, потеря остатков при импорте, скрытое увеличение повторений в нейтральном preview, повторная запись фактического подхода, разрешение до location FGS, гонка старого сервиса/новой GPS generation, потеря выбора/форм при конфигурации, чтение очищенного ID при замене упражнения и сериализация на main thread. Добавлена защита программ от перезаписи чужой истории при коллизии ID.

## Модели и совместимость

Программы хранятся в той же Room-таблице workouts как template definition с `TrainingPlan`; запланированные занятия — отдельные snapshots, связанные стабильным programDayId. Применение обрабатывает только будущие planned rows. Active/paused/done/past защищены. Повторное применение не добавляет те же слоты. План и его preview сверяются перед транзакцией.

SQL-схема остаётся v1; добавление JSON-полей не требует SQL migration. Gson-модели с defaults читают старые payload. Сгенерированная schema v1 сохраняется в `app/schemas`. `fallbackToDestructiveMigration` не используется. При следующих SQL-изменениях необходимы новые версии и реальные migration tests; текущая compilation не заменяет такой тест.

Backup v2 читается вместе с v1; активные записи импортируются на паузе. Остатки — с последнего checkpoint. Настройки/профиль/файлы картинок в формат пока не входят. Монотонные anchors чужого устройства отбрасываются.
