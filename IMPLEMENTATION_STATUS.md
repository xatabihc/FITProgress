# FitProgressAI 3.0-dev — поэтапная реализация, 2026-11-02

## GPS-карта и маршрутизация — 2026-11-02

- Добавлен MapLibre маршрутный экран: позиция из последнего GPS fix/системной последней позиции, OSM raster tiles с attribution и идентифицирующим User-Agent, записанный GPS-трек, плановая road polyline, start/end/via markers и карта с выбором координат касанием. Старт/финиш можно выбрать на карте или ввести, промежуточных точек — до 8; координатные поля на узком экране расположены вертикально. Маршруты доступны из экрана бега.
- Реализован настраиваемый Valhalla HTTP backend: costing `pedestrian` для бега/ходьбы, `bicycle` для велосипеда, `ru-RU` instructions, альтернативы при прямом запросе, несколько промежуточных точек. Перед отправкой UI сообщает, что выбранные координаты уходят на routing backend; тренировки, история и профиль туда не отправляются. Круговая дистанция ищется тремя реальными road-network запросами через промежуточные точки; прямые линии не выдаются за маршрут.
- Показаны длина, подсказки, остаток пути, предупреждение об отклонении (~45 м); ручное перестроение от последней принятой GPS-точки и к прежнему финишу. Отсутствие сети/backend не блокирует FGS GPS-запись и секундомер.
- Избранные маршруты сохраняются в существующей Room `personal_records` (`kind=route`), в Run добавлено optional navigation JSON. Room schema v2/migration не менялись. Backup v4 включает избранные маршруты и продолжает читать старые v1–v3; restore добавляет отсутствующие ID и не перезаписывает историю.
- Добавлены GPX import/export для избранного маршрута и export реальной GPS-пробежки; XML external entities отключены, диапазон координат, размер/число точек проверяются. Новые unit cases покрывают геометрию/отклонение, невалидные точки, GPX roundtrip/XXE, Valhalla payload/network failure и backup маршрутов. Добавлен неисполненный Android Room-тест сохранения/удаления избранного маршрута без изменения workout history.
- Router URL задаётся в профиле (DataStore). Default — публичный FOSSGIS Valhalla demo endpoint best-effort; user action only, X-Client-Id, частота не чаще ~1 запроса/1.2 сек. Прежде чем распространять приложение, нужно уведомить сопровождающих Valhalla через Discussions или перевести пользователей на управляемый backend. OSM стандартные тайлы имеют видимую attribution и app User-Agent; tile prefetch/offline download запрещён политикой источника.

## Данные при обновлении

`MIGRATION_1_2_SQL` создаёт только новую таблицу. Room-generated schema v2 и v1 хранятся в `app/schemas/ru.fitprogress.ai.FitDatabase/`. JVM JDBC-тест сравнивает прежние entity schema и каждое старое значение упражнений/тренировок/маршрутов. Profile/DataStore имя файла и ключи не менялись; новые поля имеют defaults. Добавлен отдельный Android-тест чтения старых ключей и атомарных изменений.

Код не переименовывает ID упражнений/истории и не выполняет удаление базы. Новая nullable muscleGroup сохраняется только в новых snapshots; старые данные остаются читаемыми. GPS-поля elapsed/boot nullable для старых точек. Active sessions сохраняют прежние правила: после прерывания GPS — пауза, после другого boot — checkpoint без выдуманного времени.

**Не подменять этими доказательствами тест реального APK upgrade.** До обновления телефона экспортировать копию, проверить тот же сертификат, установить `-r` без очистки. Старое приложение с Room v1 не предназначено для открытия базы v2.
