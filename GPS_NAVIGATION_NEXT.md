## Реализовано

- MapLibre Native отображает raster tiles OSM, последний принятый GPS fix, записанный трек, избранную/плановую дорожную геометрию и точки. На маршрутном экране точки начала/финиша/промежуточные точки выбираются касанием карты; координаты также редактируются вручную. Можно запросить последнюю системную позицию, если разрешение уже выдано.
- `ValhallaRoutingBackend` формирует `/route` JSON-запрос с `pedestrian` для бега/ходьбы и `bicycle` для велосипеда, `ru-RU` и maneuvers. Для пары точек запрашиваются до двух альтернатив, если сервер их выдаёт; промежуточные точки используют `through`.
- Круг на целевую дистанцию (1–50 км) пробует три настоящих маршрута дорожной сети через waypoint-кольцо, выбирает вариант в пределах 25% от цели либо показывает ошибку. Это best-effort приближение, не гарантия точной длины.
- Отображаются длина, статические подсказки маршрута, оценка оставшейся дистанции и предупреждение об отклонении при удалении от геометрии более чем на 45 м. Пользователь может вручную перестроить путь от последней GPS-точки к прежнему финишу.
- Избранное сохраняется в существующей Room-таблице `personal_records`; маршрут в Run хранится JSON-полем. Схема и миграции Room не изменялись. Backup v4 содержит saved routes, декодер принимает старые v1–v3; импорт добавляет отсутствующие ID.
- GPX можно импортировать в избранные маршруты и экспортировать; реальную завершённую GPS-пробежку можно экспортировать и сохранить в избранное. Валидируются XML, координаты, количество/размер точек; внешние XML entities запрещены.
- Ошибки сети, HTTP, rate limit, пустой ответ и повреждённая геометрия показываются пользователю. Маршрутизатор вызывается только после действия, запросы ограничены по частоте и получают `X-Client-Id`. Запись GPS/секундомер через foreground service не зависит от сети маршрутизации.

## Проверки кода

`NavigationTest` проверяет геодезическую дистанцию, остаток/отклонение, валидацию, GPX roundtrip/XXE, формирование Valhalla запроса и типизированный сетевой отказ, а также чтение v3 backup без поля savedRoutes и сохранение избранных маршрутов в backup v4. Android Room-тест сохранения/удаления маршрута с неизменностью истории добавлен и компилируется в Android test APK; без устройства он не исполнен. Fake transport проверяет протокол/ошибку, но не подтверждает живой ответ публичного сервера.

## Важные ограничения

- Нет офлайн-графа Valhalla и офлайн-пакета тайлов. GPS запись продолжится без сети, но tiles и новый route request будут недоступны.
- Адресный поиск и ограниченный автоматический reroute добавлены в последнем pass (см. выше), но их реальные сетевые/телефонные сценарии не проверены. Нет голосовых turn-by-turn команд, автопаузы и гарантий доступности/безопасности маршрута. Matching учитывает предыдущее продвижение; геометрическое расстояние само по себе всё ещё может быть неоднозначно в тесной застройке.
- Маршрутные подсказки — список текста от движка; экран не синхронизирует голос/сигнал по достижению каждого манёвра.
- Качество pedestrian/bicycle сети зависит от OSM coverage, freshness и выбранного Valhalla graph. GPS point snapping/доступность дороги движком физически не проверены.
- Default `https://valhalla1.openstreetmap.de` — общественный FOSSGIS demo: best-effort, fair-use/rate-limited, без SLA. Valhalla просит публичные приложения уведомлять сопровождающих через GitHub Discussions и добавлять `X-Client-Id`; это нужно сделать перед широким rollout или настроить self-hosted Valhalla backend.
- Стандартные OSM raster tiles требуют заметную атрибуцию и идентифицирующий User-Agent; bulk download и offline prefetch запрещены политикой. Для офлайн-карт надо настроить отдельный tile source с явным разрешением.
- Редактируемая настройка backend сохраняется в DataStore. Поддерживаются HTTPS и HTTP только для localhost/частных IP; настройка не резервируется JSON backup.

1. На API 29 и актуальном Android установить APK обновлением (`adb install -r`) и проверить запуск без удаления app data, Room history и settings.
2. На физическом устройстве проверить карту/attribution/zoom, выбор точек, отказ разрешения, fresh/stale last-known fix и фактические Valhalla pedestrian/bicycle результаты.
3. Пройти маршрут с выключенным экраном/без сети: проверить foreground notification, сохранение GPS, remaining/off-route, автоматическое перестроение, camera follow и восстановление после relaunch.
4. Проверить GPX import/export в системном Documents UI, включая повреждённый/большой файл и маршрут с несколькими сегментами.
5. На устройстве проверить устойчивое отклонение и ограничение частоты reroute; отдельно решить необходимость голосового сопровождения следующего манёвра.
6. Перед публичным распространением согласовать использование FOSSGIS demo или перейти на свой endpoint; проверить service-specific tile terms, кэширование, контакт и privacy notice.

## Источники и условия

- [Valhalla route API](https://valhalla.github.io/valhalla/api/route/api-reference/) описывает `pedestrian`, `bicycle`, локали инструкций, locations и ограничения alternatives для multipoint.
- [Valhalla introduction / public demo](https://valhalla.github.io/valhalla/start/introduction/) описывает fair-use/demo server и просьбу уведомлять о приложениях с `X-Client-Id`.
- [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/) требует корректный URL, visible attribution, app User-Agent и cache compliance; запрещает массовую загрузку и офлайн-предзагрузку стандартных tiles.
- [MapLibre Native Android API](https://maplibre.org/maplibre-native/android/api/) — API карты и style/layer rendering.
