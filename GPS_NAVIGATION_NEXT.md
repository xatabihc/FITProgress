# Следующий этап: маршрутизация GPS по дорогам и дорожкам

**Статус: подготовка требований. Функции построения маршрутов ещё нет.** Сейчас `MapPanel` показывает линию сохранённых GPS-точек поверх растровых OSM-тайлов; выбор старта/финиша, route engine, альтернативы и голосовые/поворотные инструкции не реализованы.

## Выбор движка и границы сервиса

Для первого маршрутизируемого прототипа предпочтителен **Valhalla**: его API включает `pedestrian` и `bicycle` costing, а `trace_route` умеет привязать записанные GPS-точки к нанесённым на OSM дорогам/тропам. Это не означает, что любой путь на карте безопасен или доступен для бега: результаты зависят от тегов OSM и их актуальности. См. [Valhalla route API](https://valhalla.github.io/valhalla/api/route/api-reference/), [costing models](https://valhalla.github.io/valhalla/sif/dynamic-costing/) и [map matching](https://valhalla.github.io/valhalla/api/map-matching/api-reference/).

Не привязывать клиент к публичному demo endpoint как к production SLA. Нужен конфигурируемый `RoutingDataSource`: сначала тестовая/развёрнутая нами Valhalla-служба с ограничением запросов и понятной политикой хранения координат; для публичной поставки выбрать хостинг и проверить его условия/лицензии. Не отправлять маршрут на сервер до явного действия пользователя. Не обещать полностью офлайн-маршруты: для них потребуется локальный граф/отдельная сборка данных, оценка размера и процесса обновления.

Текущий MapLibre остаётся renderer-ом: он умеет загружать style и отображать sources/layers. Слой маршрута должен быть отдельным GeoJSON source поверх базовой карты, не подменяя реальную запись `RunService`. См. [MapLibre Native Android Style API](https://maplibre.org/maplibre-native/android/api/).

## Порядок реализации

1. **Зафиксировать контракт:** `RouteRequest(start, finish, mode, distanceTarget?, avoid?)`; результат содержит геометрию, измеренную длину, ETA от движка, snapped start/end, предупреждения и инструкции с индексами манёвров. Серверный ETA — оценка, не результат тренировки.
2. **Проверить картографическое снабжение:** текущий `tile.openstreetmap.org` используется только для активного просмотра, с видимой атрибуцией. Проверить стабильный уникальный User-Agent и поведение кэша MapLibre: OSMF требует идентифицировать приложение, уважать cache headers и запрещает bulk prefetch/offline загрузку на стандартном raster tile сервере. Для offline tiles — только self-host/provider с разрешёнными условиями. [OSMF tile policy](https://operations.osmfoundation.org/policies/tiles/).
3. **Реализовать data/domain слой:** `RoutingRepository`, Valhalla REST adapter на IO dispatcher, таймауты, отмена старых запросов, валидация координат/GeoJSON/encoded polyline, ошибки `NoRoute`, `Offline`, `RateLimited`, `InvalidResponse`. Базовые GPS-сервис и Room не зависят от доступности маршрутизатора.
4. **Экран построения:** старт из текущей геопозиции или выбранной точки, финиш по касанию карты/поиску, режим «бег пешком»/«велосипед», целевая длина только если engine действительно возвращает loop alternatives. Показывать несколько вариантов лишь при наличии разных валидных геометрий; прямую линию запрещено выдавать за маршрут.
5. **Предпросмотр/редактирование:** длина сети, геометрия и доступные манёвры, явная отметка «данные OSM, возможны ошибки», сохранение избранного маршрута, повторное использование. До нажатия «Начать запись» не менять текущую GPS-тренировку.
6. **Сопровождение пробежки:** сравнение GPS position с коридором route geometry, защита от шумных точек, off-route сообщение только после нескольких устойчивых фиксов; маршрутная запись и таймер продолжаются, если engine/сеть потеряны. Пересчёт по запросу пользователя или с cooldown, никогда не подменяет исходный маршрут.
7. **Проверки:** unit-тесты decode geometry/maneuvers, snapping, route deviation и невалидных ответов; repository tests для timeout/offline/retry/cancel; UI tests выбора старта/финиша и пустых ошибок; API29/API35 + физический GPS test; сценарии без сети, provider 429/5xx, неоднозначный/закрытый участок, relaunch и отказ геолокации.

## Критерии выпуска маршрутизации

- Возвращается настоящая сеть дорожек/проходов от маршрутизатора; нет straight-line fallback.
- Пешеходный costing не прокладывает маршрут по автомобильным-only участкам по возможности движка; неподтверждённые доступы/частные территории маркируются или исключаются.
- Пользователь видит источник, атрибуцию, режим, расстояние, состояние подключения и ошибку построения.
- Нет сети: можно стартовать обычную GPS-запись без маршрута; UI не изображает её как навигацию.
- GPS service, Room history и backup остаются независимыми от маршрутизатора; история прошлых пробежек не переписывается map matching-ом без отдельного действия.
- Лицензии OSM-данных/тайлов и выбранного tile/routing host проверены, атрибуция видна и настройки User-Agent/кэширования подтверждены на устройстве.
