# FitProgressAI 2.0 Ultimate — development

Развитие существующего Android-приложения FitProgressAI. Kotlin, Compose Material 3, MVVM/Repository, Room, DataStore, Navigation, Fused Location, MapLibre и WorkManager. Android 10+ / API 29, compile/target 35. Аккаунт и платные серверы не нужны.

**Текущая версия — `2.0-dev`, не завершённая Ultimate.** Новый подписанный debug APK создаётся и проверяется SDK-инструментами из локального кэша. Стандартный Gradle build блокируется средой. Установка, запуск, фоновые таймеры/GPS и инструментальные тесты на Android пока не проверены. Полная матрица — [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md); исходный аудит — [docs/AUDIT_V2.md](docs/AUDIT_V2.md).

## APK и установка

Файл: `app/build/outputs/apk/debug/app-debug.apk`. Пакет `ru.fitprogress.ai`, versionCode 2, versionName `2.0-dev`. Проверки подписи, manifest, размера и SHA-256 сохраняются в `docs/verification/v2/apk.json` и соседних логах.

После подключения телефона с разрешённой USB-отладкой:

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Или перенесите APK на телефон и разрешите установку из файлового менеджера. Использована локальная debug-подпись. Обновляйте с той же подписью через `-r`, чтобы сохранить базу; перед обновлением экспортируйте JSON. Если подписи установленной версии и APK отличаются, не удаляйте приложение без резервной копии.

## Обычная сборка из чистого checkout

JDK 17, Android SDK 35, доступ к Google Maven/Maven Central/Gradle distribution. Откройте корень в Android Studio, укажите SDK в локальном `local.properties` либо `ANDROID_HOME`, выполните Sync. Затем:

```bash
./gradlew testDebugUnitTest
./gradlew lintDebug
./gradlew assembleDebug
./gradlew connectedDebugAndroidTest  # устройство или эмулятор
```

На Windows используйте `gradlew.bat`. Gradle Kotlin DSL и версии зависимостей сохранены: AGP 8.9.2, Gradle 8.11.1, Kotlin/Compose compiler 2.1.20, Compose BOM 2025.04.01, Room 2.7.1, Navigation 2.8.9, DataStore 1.1.1, WorkManager 2.10.0, Location 21.3.0, MapLibre 11.8.0. SDK 35 выбран для совместимости с этим стеком; minimum 29 обеспечивает Android 10+.

В текущем sandbox Gradle не может создать wrapper lock в `~/.gradle`. С writable временным Gradle home daemon не может открыть сокет (`SocketException: Operation not permitted`). Поэтому успешные Gradle Sync, `assembleDebug`, `testDebugUnitTest` и `lintDebug` не заявляются.

### Дополнительная offline-проверка в текущей среде

```bash
./tools/run-domain-tests.sh
python3 tools/offline-android-build.py --android-tests --package
```

Второй скрипт — **сборка из существовавших Gradle intermediates**, не clean build. Он требует уже скачанные зависимости, SDK/build-tools 35, сгенерированные Room v1 Java sources, объединённые ресурсы/stable resource IDs, dependency DEX и предыдущий APK для неизменённых native libraries/assets. Скрипт заново компилирует весь Kotlin/Compose код, Room Java, Android-тесты; запускает D8, AAPT2, zipalign и apksigner. При успехе помещает новый APK в стандартный каталог. Код приложения и DEX предыдущего приложения не переиспользуются. Подпись — обычным локальным debug keystore; release-ключ не требуется.

Это позволяет проверить компиляцию и создать APK в этой сессии, но не заменяет Gradle resolution/KAPT regeneration, Lint, clean build и Android smoke-тест. После изменения схемы, ресурсов или зависимостей используйте обычный Gradle build. Manifest зависимостей и native/assets берутся из предыдущей сборки; точные source fingerprints сохраняются в `app/build/offline-verification/`.

## Проверка силовой тренировки

1. **Каталог → Создать упражнение**. Укажите название, категорию, технику, мышцы, оборудование, подходы, повторения, кг, секунды, отдых и заметки. Можно выбрать локальное изображение; при недоступном URI отображается локальная иллюстрация.
2. Откройте упражнение и измените название. ID сохраняется; история связана по ID и хранит снимок названия. Встроенное упражнение редактируется через пользовательскую копию.
3. **Главная → Создать тренировку → Добавить упражнение**. Меняйте отдельные подходы, порядок, отдых, группу суперсета, заметки и дату.
4. В подходе доступны 11 типов, вес, повторения, секунды, метры, отдельный отдых, RPE/RIR и комментарий. Типы — метки и параметры журнала: автоматического исполнения дроп-/гигантских/круговых последовательностей пока нет.
5. **Начать тренировку**. На Android 13+ запросится разрешение уведомлений. Сервис показывает постоянное уведомление; секундомер и deadlines используют `elapsedRealtime`, а дата результата — wall clock.
6. Подтвердите фактический подход: отдых запускается автоматически. Его можно изменить, запустить отдельно или пропустить. Временной этап запускается кнопкой таймера, после сигнала результат подтверждается вручную.
7. Во время занятия можно добавлять подходы/упражнения, менять порядок, копировать последний выполненный результат и заменять упражнение без выполненных подходов. Выполненное нельзя случайно удалить/заменить; повторное подтверждение не перезаписывает результат и не перезапускает отдых.
8. Поставьте паузу и продолжите. Сверните приложение, поверните экран, заблокируйте телефон; затем проверьте время, остаток и фактические подходы. Проверка на устройстве обязательна: в этой среде она не выполнена.
9. **Завершить и сохранить**: оцените сложность, восстановление и наличие боли. Сохраняются фактически отмеченные подходы, время, объём и сравнение с предыдущим составом упражнений. Завершение требует отдельного подтверждения.
10. История доступна в календаре и через последнюю тренировку на главной. **Прогресс** использует только сохранённые реальные данные; демо исключается.

## Своя многонедельная программа

**Главная → Программы → Создать свою программу**:

- Название, начало, заметки, 1–52 недели.
- Визуальный выбор недели и семи дней от начала программы.
- Занятия с разным составом упражнений/подходов; явные дни восстановления.
- Перенос дня через его номер от начала, тренировочные блоки, копирование недели с подтверждённой заменой целевой недели.
- Разгрузка выбранной недели: число подходов уменьшается примерно на 30%, минимум один; повторное нажатие не снижает их повторно.
- Сдвиг всего определения программы по дням.
- Предварительный просмотр количества добавляемых/изменяемых/удаляемых будущих занятий.

Редактор сначала сохраняет **определение** программы. Календарь меняется только после **Просмотреть и применить будущий план → Подтвердить изменения**. Обновляются только плановые занятия с датой не раньше сегодняшней; прошлые, активные и завершённые защищены. Повторное применение использует те же слоты, не создаёт дубли. Если определение изменилось после preview, применение отклоняется. Конфликт ID не перезаписывает чужую историю.

Сохранённые программы входят в JSON-копию. Они хранятся как отдельные template snapshots в существующей Room-таблице: SQL-схема v1 не менялась, destructive migration не нужна и не используется.

Существующие 35 готовых программ сохранены. Это конкретные общие расписания; экспертная спортивная проверка и расширение библиотеки по всем направлениям 2.0 остаются задачами. Программы и рекомендации не являются медицинскими назначениями.

## Календарь и рекомендации

Календарь поддерживает день, неделю, месяц, переход по дате, дни восстановления, перенос отдельной плановой тренировки, копирование прошлой недели в выбранную и шаблоны тренировок. Раздел программы предоставляет недельное представление цикла; отдельного объединённого режима «цикл» в календаре пока нет.

Локальные рекомендации анализируют предыдущую завершённую неделю: выполнение, дни активности, сложность, боль и восстановление. Доступны сохранение, осторожная прогрессия при выполнении условий, облегчение и ручной вариант. При боли, сложности ≥9/10 или восстановлении ≤3/10 прогрессия не предлагается. Изменения применяются после просмотра и подтверждения. Нейтральный вариант теперь сохраняет повторения и временные этапы без скрытого увеличения. Все шесть вариантов Adaptive Coach и анализ многонедельных трендов ещё не завершены.

## Бег и проверка GPS

1. Нужен телефон с Google Play Services, геолокацией и точным разрешением. **Бег → Начать пробежку** запрашивает необходимые разрешения. Приблизительного разрешения недостаточно для записи.
2. Выйдите на открытое место. До точных точек километраж не растёт. Запись работает в location foreground service с постоянным уведомлением.
3. Пройдите/пробегите 300–500 м. Заблокируйте экран на 15 минут. Проверьте продолжение записи, время и маршрут — это пока не проверено на физическом устройстве.
4. Пауза → переместитесь → продолжение. Соединение через паузу не добавляет расстояние.
5. Выключите Wi-Fi/мобильную сеть, оставив GPS. Измерение должно продолжаться. При отсутствии тайлов MapLibre отображается локальная схема маршрута; ручное скачивание регионов не реализовано.
6. Завершите и откройте историю. Проверяйте дистанцию, средний/текущий темп и скорость, отсечки по 100 м, лучшие непрерывные отрезки 1/3/5/10 км. «В движении» — оценка по принятым GPS-точкам, а не отдельное измерение датчика.
7. Отзовите разрешение, выключите геолокацию, проверьте потерю сигнала и force stop. Ошибка не должна заменяться синтетическим маршрутом. После прерывания сервиса восстанавливается пауза. GPS без GMS, автопауза, цели, звуковые километровые отсечки и сравнение маршрутов пока не реализованы.

Фильтр отклоняет точность хуже 35 м, старые точки, шум ниже порога точности и скорость выше 12 м/с. Разрыв >120 секунд создаёт новый участок без выдуманного соединения. Погрешность GPS остаётся. Демо помечено и исключено из аналитики.

**Записать беговую дорожку вручную** сохраняет введённые километры, время и дату с пометкой `manual`. GPS-точки не создаются, в GPS-рекордах такая запись не участвует. В аналитике GPS- и ручной километраж показаны отдельно.

## Настройки, данные и разрешения

Профиль, тёмная/светлая тема, отдых по умолчанию, звук и вибрация таймеров, недельное уведомление — через DataStore. Пока только метрические единицы. Неделя начинается в понедельник.

Разрешения: точная/приблизительная геолокация; location foreground service; specialUse foreground service для запущенного пользователем секундомера/таймеров; уведомления Android 13+; вибрация; wake lock на время активного countdown/GPS; интернет/состояние сети для карты. Фоновая геолокация `ACCESS_BACKGROUND_LOCATION` не запрашивается. Системный выбор файлов не требует доступа ко всему хранилищу.

JSON backup v2 содержит пользовательские упражнения, планы, определения программ, результаты, подходы и маршруты. Чтение v1 сохранено. Проверяются версия, структура, checksum SHA-256, диапазоны и ID; импорт атомарно добавляет отсутствующие записи, не заменяет существующие. Активные занятия импортируются на паузе без чужих монотонных anchors, с последними сохранёнными остатками таймеров. Максимум файла — 20 МБ. CSV включает новые параметры подходов и явно различает GPS/ручной бег. Запись файлов выполняется только после пользовательского выбора через SAF.

Профиль, настройки и двоичные изображения в переносимую копию пока не входят. URI другого устройства может быть недоступен; fallback локальный. SHA-256 проверяет повреждение, не является шифрованием/подписью. Данные хранятся локально, реклама и серверная аналитика отсутствуют, Android cloud backup отключён. Поставщик OSM-тайлов получает сетевые запросы карты. Удаление данных требует подтверждения и завершения активных занятий.

## Проверки и продолжение

Реально пройдены **58 JVM-тестов**. Полный Kotlin/Compose-код, существующий Room Java и 10 Android-тестов компилируются дополнительным offline-инструментом. Android-тесты **не выполнены**; Lint и стандартный Gradle build заблокированы. APK подписан и проверен, но установка/launch/GPS/таймеры на телефоне не подтверждены.

Подробная матрица и команды — [TESTING.md](TESTING.md). Изменения — [CHANGELOG.md](CHANGELOG.md). Полный остаток требований — [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

Ближайший приоритет: clean Gradle build и Lint в доступной среде, установка с обновлением v1, прогон Room/UI-тестов, реальные GPS/таймеры с выключенным экраном, проверка малого экрана/крупного шрифта. Затем — дневник самочувствия, цели, полный Adaptive Coach и остальные P1/P2.
