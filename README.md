# FitProgressAI 2.1-dev

Развитие существующего Kotlin/Compose-приложения для локальных тренировок и бега. Android 10+ (API 29), compile/target 35, без регистрации и платных серверов.

**Это проверяемая development-сборка, ещё не подтверждённый стабильный релиз 2.1.** APK собирается доступными SDK-инструментами; стандартный Gradle и ADB блокируются средой. Установка на телефон, реальные GPS/lock screen и исполнение Android-тестов пока не проверены. UI-тесты переведены на отдельные базу и профиль через FitTestRunner, чтобы их подготовка не очищала обычную историю. Полная матрица — [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md), команды — [TESTING.md](TESTING.md), аудит обновления — [docs/AUDIT_2_1.md](docs/AUDIT_2_1.md).

## APK и установка

Новый файл: `app/build/outputs/apk/debug/app-debug.apk`. Application ID `ru.fitprogress.ai`, versionCode **3**, versionName **2.1-dev**. Размер, SHA-256, проверка подписи, DEX-классов и соответствия исходникам — `docs/verification/v2.1/apk.json`.

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Или перенесите APK на телефон и разрешите установку из файлового менеджера. Сначала экспортируйте JSON из установленного приложения. Обновляйте **с той же подписью** через `-r`; не удаляйте приложение и не очищайте его данные ради обновления. Новый APK подписывается тем же локальным debug-ключом, что сохранённая исходная сборка 2.0-dev. Совпадение сертификата проверяется инструментом, установка пока не проверена.

Room теперь версии 2: миграция 1→2 добавляет таблицу целей/дневника, не удаляя и не переписывая таблицы тренировок, упражнений и маршрутов. APK старых версий с Room v1 не рассчитаны на открытие базы v2 — откат поверх новой базы не поддержан. Для возврата к старой версии потребуется отдельная совместимая копия, не удаление единственной истории.

## Сборка

JDK 17, Android SDK Platform/build-tools 35 и доступ к Google Maven, Maven Central и Gradle distribution. Откройте корень в Android Studio, укажите SDK в `local.properties`/`ANDROID_HOME`, выполните Sync:

```bash
./gradlew testDebugUnitTest
./gradlew lintDebug
./gradlew assembleDebug
./gradlew connectedDebugAndroidTest  # устройство или эмулятор
```

Windows: `gradlew.bat`. Сохранены AGP 8.9.2 / Gradle 8.11.1, Kotlin + Compose compiler 2.1.20, Compose BOM 2025.04.01, Room 2.7.1, Navigation 2.8.9, DataStore 1.1.1, WorkManager 2.10.0, Location 21.3.0, MapLibre 11.8.0. SQLite JDBC 3.41.2.2 используется только в JVM-тестах миграции, в приложение не добавлен.

В текущем sandbox wrapper не может создать lock в read-only `~/.gradle`. Writable home не снимает запрет daemon socket. Эти команды не объявляются успешными.

### Доступная локальная проверка/упаковка

```bash
./tools/run-domain-tests.sh
python3 tools/offline-android-build.py --android-tests --package
python3 tools/verify-apk.py --baseline /путь/к/исходному-2.0.apk
```

Offline-сборка требует имеющиеся кэшированные библиотеки, merged resources/stable IDs, dependency DEX и предыдущий APK для неизменённых native libraries/assets. Она регенерирует Java и schema официальным Room-процессором через локальный KAPT, компилирует Kotlin/Compose и Java, компилирует Android-тесты, выполняет D8/AAPT2/zipalign/apksigner. **Это не clean Gradle build, не Lint и не исполнение тестов на Android.** После изменения зависимостей/ресурсов необходима обычная Gradle-сборка. Kotlin/DEX приложения собираются заново, старый код приложения не переносится.

## Основные сценарии

**Каталог → Создать упражнение**: название, категория, техника, мышцы, оборудование, изображение, подходы/повторы/вес/время/отдых/заметки. Пользовательское упражнение можно изменить, дублировать, удалить; встроенное редактируется через копию. История связана по ID и хранит снимки результатов. Недоступное изображение заменяется локальной иллюстрацией.

**Главная → Создать тренировку**: добавьте упражнения, поменяйте порядок, дату и параметры отдельных подходов. Поддерживаются 11 типов и поля веса, повторений, секунд, метров, отдельного отдыха, RPE/RIR и комментария. Во время занятия доступны добавление, перестановка, копирование прошлых результатов и замена невыполненного упражнения. Выполненный подход/упражнение защищён от случайной повторной записи и удаления.

**Начать тренировку → отметить фактический подход → завершить и сохранить**. Отдых стартует автоматически; можно изменить, пропустить, поставить на паузу. Секундомер и deadlines используют `elapsedRealtime` и boot ID. Отдельный foreground service подаёт сигналы независимо от Activity; звук/вибрация настраиваются. Временные этапы подтверждаются вручную: автоматического переключения сложных кругов/дроп-сетов нет. Завершение требует подтверждения и оценки сложности/восстановления/боли. История — в календаре, последняя тренировка — на главной.

## Персональные цели

**Главная → Персональные цели**:

- Количество записанных занятий за выбранный период.
- Километраж с выбором всех/GPS/ручных записей.
- Средний темп на сохранённой пробежке не короче 1 км.
- Рабочий вес выбранного упражнения при заданном минимуме повторений; разминочные подходы не засчитываются.
- Завершение выбранной программы.
- Число календарных недель с заданной частотой занятий.

Можно вести несколько целей, менять параметры и архивировать. Прогресс/история рассчитываются из завершённых записей, демо исключено. Даты включительны; до начала периода достижения не начисляются. Истёкшая цель показывает фактический результат, не выдуманную причину невыполнения. Темп вводится десятичными мин/км: 5,5 = 5:30. Плановая программа должна иметь занятия в выбранном периоде.

## Дневник самочувствия

**Главная → Дневник самочувствия**: энергия, усталость, сон, мышечная болезненность, восстановление, боль и комментарий. Запись необязательна для тренировки. На дату хранится одна редактируемая запись; удаление требует подтверждения. При сохранении на другую дату исходная запись остаётся, существующая запись выбранной даты обновляется. Будущие оценки не принимаются. Значения сохраняются только после вашего подтверждения; дневник не заполняется автоматически.

## Adaptive Coach

**Главная → План следующей недели**. Анализируются две предыдущие календарные недели, реальная нагрузка, километраж, выполнение, дни активности и структурированные оценки дневника вплоть до сегодняшнего дня.

Шесть вариантов: повторить фактические подходы прошлой недели; сохранить исходный план; осторожная прогрессия; уменьшить объём; добавить восстановление; настроить вручную.

Прогрессия недоступна при боли; усталости ≥8, восстановлении/энергии/сне ≤3, болезненности ≥8; сложности тренировки ≥9; скачке недельного объёма/километража >15%; менее двух дней отдыха; недостаточном выполнении/двух разных днях занятий; отсутствии дневника или тренировочной базы предыдущей недели. Это консервативные локальные правила, не диагноз. Комментарии свободным текстом не интерпретируются как медицинские данные.

Для подходящих обычных/рабочих силовых подходов предлагается до +2,5% веса с округлением вниз до 0,1 кг или +1 повторение без веса. Временные, дистанционные и специальные подходы автоматически не повышаются. Уменьшение объёма сохраняет разминку и минимум один рабочий подход. Добавление восстановления заменяет последнее по дате силовое занятие днём отдыха.

Перед применением видны «было/станет» и число заменяемых **плановых занятий целевой недели, включая занятия программ**. Прошлая история не меняется. Данные и ограничения перепроверяются в транзакции; устаревший preview отклоняется. Применение одной рекомендации на неделю защищено от повторов. После этого можно редактировать план вручную. Самостоятельные пробежки без плановой Workout-записи анализируются, но не превращаются автоматически в новый беговой план.

## Аналитика

**Прогресс → Расширенная аналитика**: периоды 7/30/90/365 дней и сравнение с непосредственно предыдущим периодом той же длины, фильтр источника бега, графики с выбором даты ползунком.

Показаны количество записей, время, реальные дни активности, силовой объём, повторения/максимальный выполненный вес по упражнениям, объём по основной мышечной категории, GPS/ручные километры отдельно, темп, средние оценки усталости/восстановления. e1RM по Эпли (1–10 повторений) помечен как **оценка**, а не выполненный максимум. Каждый подход учитывается в основной группе один раз; для старых записей группа берётся из каталога либо отмечается как неизвестная. Дата выполненной тренировки — фактический финиш, дата в календаре остаётся плановой.

## Программы и календарь

Существующие 35 общих программ сохранены; экспертная спортивная валидация не заявляется. Своя программа поддерживает **любую целую длительность 1–52 недели**. В одном определении — до 364 записей дней/занятий. Дни с разными упражнениями, отдельные подходы/отдых/заметки/суперсеты, порядок упражнений, удаление подходов, восстановление и блоки.

Нажмите **Неделя N из M**, чтобы перейти непосредственно к нужной неделе. Есть копирование недели, повторение выбранной недели до конца программы с подтверждённой заменой последующих недель, разгрузка и сдвиг старта. При сокращении сначала перенесите/удалите дни вне нового срока.

Редактор сохраняет определение. Календарь меняется только после preview и подтверждения. Защищены completed/active/paused/past записи; повторное применение не создаёт те же слоты заново. Календарь имеет день/неделю/месяц, перенос отдельного занятия, восстановление, шаблоны и копирование недель. Независимые повторные запуски одного определения и сроки свыше 52 недель пока не поддержаны.

## Бег и проверка lock screen

Нужны Google Play Services, включённая геолокация и точное разрешение. На Android 13+ запрашиваются уведомления. Запись начинается на видимом экране, продолжается в location foreground service с постоянным уведомлением.

1. **Бег → Начать пробежку** на открытом месте; до точных точек расстояние нулевое.
2. Пройдите 300–500 м, заблокируйте экран на 15–30 минут; проверьте маршрут, время и расстояние. На конкретном устройстве проверить ограничения батареи обязательно.
3. Пауза → перемещение → продолжение: путь через паузу не добавляется.
4. Выключите интернет, оставив GPS: координаты продолжают записываться; при отсутствии тайлов остаётся локальная схема.
5. Отзовите разрешение/выключите геолокацию: ожидается пауза и ошибка. Уничтожьте процесс, откройте снова: незаписанное время не засчитывается, бег восстанавливается на паузе.
6. Перевод системных часов не должен менять GPS-интервалы/темп: новые точки используют elapsed time и boot ID. Старые маршруты читаются с прежними wall-time метками.

Фильтруются отсутствующая/плохая точность (>35 м), старые точки, шум и невозможная скорость (>12 м/с). Тестовые координаты Android не записываются как реальная пробежка. Длительная потеря сигнала создаёт новый сегмент без выдуманного соединения. GPS wake lock обновляется до истечения срока и освобождается при паузе/остановке. Полная физическая проверка этих механизмов ещё не выполнена.

В истории: карта/локальная схема, темп/скорость, отсечки 100 м и лучшие непрерывные отрезки 1/3/5/10 км. Время движения — оценка по точкам. Звуковые/вибро-отсечки каждого километра включаются отдельно в настройках и используют общие переключатели звука/вибрации. Автопауза, сравнение маршрутов и полноценный run interval controller остаются задачами.

**Беговая дорожка вручную** сохраняет введённые км/мин/дату с пометкой `manual`, без GPS-точек. Демо и ручные записи не выдаются за GPS-измерение; демо исключено из аналитики/целей/Coach.

## Настройки, уведомления и данные

DataStore: профиль, тема, три акцента, отдых, звук/вибрация, интернет-карта, недельный анализ и плановые напоминания. Карта отключается без потери локальной схемы. Метрические единицы и понедельник пока фиксированы.

Напоминания о плане выключены по умолчанию. Выберите час 0–23 и разрешите уведомления: WorkManager проверяет план примерно каждые 15 минут; Android/Doze может задержать выполнение. Это не точный будильник. Повторы за один день подавляются. Переключатели обновляются атомарно и не перезаписывают соседние настройки.

Room v2 добавляет `personal_records` (цели, дневник, подтверждения Coach) к прежним трём таблицам. Миграция — только CREATE TABLE, без DROP/DELETE и destructive fallback. DataStore сохраняет прежнее имя файла/ключи. Перед обновлением/тестами сделайте копию; фактическое обновление установленного приложения в этой среде не проверялось.

JSON backup **v3** включает новые цели, дневник и подтверждения Coach вместе со всей прежней историей/программами. Читаются v1/v2. Структура, checksum, диапазоны, ID и ограничения проверяются; экспорт проходит проверку обратного чтения **до записи**. Импорт атомарно добавляет отсутствующие записи, существующие не заменяет; активные занятия импортируются на паузе без чужих anchors. Максимум — 20 МБ; слишком большая/некорректная копия отклоняется явно. Для большой многолетней истории нужен дальнейший streaming-формат.

CSV содержит историю тренировок/бега; цели и дневник восстанавливаются из JSON. Профиль, настройки и двоичные изображения пока не входят в переносимую копию, но сохраняются при обычном обновлении приложения. Файлы записываются через системный выбор SAF только по действию пользователя. Недоступный URI изображения имеет fallback. Удаление данных требует подтверждения и завершения активных занятий. Скрытой отправки истории/дневника, рекламы и аналитических SDK нет; запросы карты получает поставщик OSM-тайлов.

## Результат проверок и следующий шаг

JVM-набор: **102 теста**, включая точный SQL миграции на 10 000 строк с побайтным сравнением истории, цели/дневник/Coach/аналитику/напоминания, реальное чтение старой структуры backup v2 и GPS при переводе часов. Полный Android-код, regenerated Room Java и **15 инструментальных тестов компилируются**. Исполнение Room/UI-тестов, реальный lock screen/GPS, small screen и обновление поверх установленной 2.0-dev **не проверены**.

До стабильного релиза 2.1: clean Gradle build + Lint, установка/обновление на API 29/35, прогон 15 Android-тестов, физический GPS/батарея/lock screen и визуальный smoke на малом экране/font scale 2.0. Числа и логи см. в `docs/verification/v2.1/`.
