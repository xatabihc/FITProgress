# Автоматическое тестирование FitProgressAI

Безопасный запуск из корня проекта:

```bash
./scripts/android_qa.sh
```

Python 3 (без pip), Java 17, Android SDK build-tools 35.0.0 и ADB должны быть доступны. Подключите физический телефон с ранее разрешённой отладкой. При нескольких устройствах укажите `--serial SERIAL`. Эмулятор не подменяет аппаратные результаты.

По умолчанию выполняются Gradle unit/lint/build, аудит ресурсов, чтение батареи/ОС/места/разрешений, проверка сертификатов установленного и локального APK, ограниченная диагностика текущего процесса. Реальные тренировки и история не читаются. Скриншоты и XML пользовательских экранов не сохраняются.

После явного разрешения владельца и завершения активной тренировки:

```bash
./scripts/android_qa.sh --serial SERIAL --isolated-idle-confirmed --approve-install
```

Флаг подтверждает разрешение установить именно текущую локальную сборку и тестовый APK. Повторное изменение исходников требует нового подтверждения. Перед установкой проверяются SHA256 сертификатов и versionCode; несовпадение, неизвестная подпись, downgrade и split APK блокируют обновление. Используется только `adb install -r` (для тестового APK также `-t`). Удаления приложения, `pm clear`, выдачи разрешений и изменения настроек нет. Ротация ключей автоматически не разрешается.

`--isolated-idle-confirmed` без `--approve-install` запускает только уже установленную побайтово совпадающую сборку и test APK. `--skip-build` пропускает локальную сборку и не засчитывает её.

## Изоляция и сценарии

Существующий FitTestRunner создаёт FitTestApplication с `isolatedTestStorage=true`: отдельные `fitprogress-instrumentation.db` и DataStore, фоновые задания выключены. Тесты проверяют флаг перед изменением фикстур. Production-база не очищается. Инструментация останавливает процесс приложения, поэтому телефон должен быть свободен.

MainFlowTest проверяет план, сохранение тренировки, пересоздание Activity, цели и дневник; ExerciseLibraryTest — каталог и фильтры; RunStartUiTest — ошибки старта GPS. AndroidQaTest добавляет ограниченный обход (2 цикла, 8 переходов, 16 прокруток), поиск/пустую выдачу/восстановление, снимок Compose без системных панелей и структурную Compose semantics hierarchy без текста. Отдельный тест проверяет фон/возврат и поворот Activity с восстановлением поискового запроса. Глобальная настройка автоповорота не меняется. Это не доказательство полноты обхода всех экранов и визуальной читаемости.

Используется Compose UI test и семантическая иерархия Compose, а не библиотека UI Automator/UiDevice или Espresso: приложение Compose, дополнительные тяжёлые зависимости не нужны. Обычный `connectedAndroidTest` автоматически устанавливает APK без наших предварительных проверок; на пользовательском телефоне оркестратор использует сборку test APK и `am instrument`. Для отдельного тестового устройства допустим `./gradlew --no-parallel --max-workers=2 connectedDebugAndroidTest`, но только после проверки подписи и разрешения владельца.

GPS hardware test по умолчанию пропускается: аргумент `gpsService=true` не передаётся. GPS mock, переключение сети/GPS/языка, проверка живого маршрута требуют отдельного сценария и разрешения. Mock-маршрут не доказывает реальную точность. Monkey не запускается. Автоматических исправлений без воспроизводимого подтверждения нет. Подтверждённые устаревшие селекторы и фикстуры существующих тестов исправлены; прикладной код этим набором не изменялся.

## Артефакты

`qa-reports/YYYYMMDD-HHMMSS-microseconds/`: report.html, report.md, results.json, gradle.txt, device.json, permissions.json, localization.json, ограниченные CPU/RAM и logcat-маркеры при наличии процесса. PASS/FAIL/BLOCKED/NOT TESTED относятся к конкретному утверждению. Статический аудит литералов — диагностическая эвристика; не подтверждает отображаемый язык. FAIL содержит критичность, способ повторения и возможную причину. Ошибки инфраструктуры отделены от ошибок функций.

Полный logcat не публикуется: сообщения, координаты, токены и пользовательский текст не включаются. Каталог отчёта имеет права 0700 и исключён из Git. Compose-артефакты снимаются только в изолированном каталоге, hierarchy не содержит текст/описания/ID. Перед передачей отчёта всё равно просмотрите изображения: в повторно используемых тестовых фикстурах могут быть введённые ранее сведения.

Генератор можно повторить: `python3 scripts/android_qa_report.py qa-reports/КАТАЛОГ`. Код выхода оркестратора 1 при FAIL; BLOCKED отражается в отчёте и не означает PASS.

Нагрузка последовательная: Gradle workers=2, heap=1024 МБ, Kotlin in-process; таймаут сборки 30 минут, инструментации 10 минут, обычной команды 60 секунд. Таймаут инструментации не очищает данные; проверьте оставшийся процесс перед следующим запуском.

## Сохранность тестовой истории и диагностика

Полный одобренный прогон дополнительно вызывает AndroidQaPersistenceTest в фазе seed, повторяет проверенное обновление `install -r`, затем вызывает verify в новом процессе. Проверяются статус завершения, один выполненный подход и объём 160. Идентификатор тестового маркера уникален; production-история не читается. В обычном запуске всего test suite этот тест пропускается без аргументов фазы, затем запускается оркестратором отдельно.

Во время инструментации каждые 5 секунд снимаются ограниченные выборки CPU/RAM и crash-маркеры текущего PID (`performance.json`). Это не непрерывная трассировка; пики между выборками и некоторые системные ANR могут быть пропущены. Подробный текст logcat исключён из-за возможных секретов, безопасные stack frames тестов находятся в `failure-frames.txt`.

Для повторения отдельного падения: `./scripts/android_qa.sh --isolated-idle-confirmed --test-class 'ru.fitprogress.ai.MainFlowTest#имяМетода'`. Test APK должен уже совпадать с установленным; при добавлении `--approve-install` он собирается и устанавливается с проверками. Фильтр не выполняет обновление с тестовым маркером.

Первоначальные неуспешные прогоны сохраняются отдельно, не перезаписываются. Они не являются итоговыми результатами после исправления тестов. Сам по себе код возврата `am instrument` не подтверждает успех: проверяются итоговая строка JUnit и статусы каждого метода; пропуски учитываются отдельно.

`--gps-service` разрешает аппаратный тест старта, паузы, возобновления и завершения GPS-сервиса **в изолированном хранилище**. Он использует уже выданное разрешение и текущее состояние GPS; при отсутствии условий — NOT TESTED. Настройки не меняются, mock не включается. Координаты не экспортируются в отчёт. Этот тест проверяет сервис/часы/сохранение, а не пройденный живой маршрут и точность позиционирования.

В тестовой фикстуре ViewModel устранена воспроизведённая гонка: отмена scope теперь дожидается завершения читателей Room перед закрытием in-memory базы. Ранее она давала `connection pool has been closed` в следующем тесте; это не означало порчу production-базы.

## Отдельная установка при несовместимой подписи — 3.1 RC1

Если сертификат обычного установленного приложения не совпадает с доступным ключом, его нельзя обновлять или удалять ради тестов. Соберите отдельный пакет:

```bash
./gradlew --no-daemon --max-workers=2 -PfitQa=true testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
python3 tools/verify-device-qa.py --serial SERIAL --output /tmp/fitprogress-device-report
```

Второй скрипт предназначен для авторизованной проверки физического телефона. Он устанавливает только `ru.fitprogress.ai.qa` и его test APK, проверяет сертификаты прежней QA-установки, разрешает уведомления и точную геолокацию **только отдельному QA-пакету**, выполняет suite и seed/install-r/verify тестовой истории. Глобальные настройки геолокации, сети, шрифта и блокировки не меняются. При выключенном GPS проверяется отказ сервиса без создания записи; запись физического маршрута этим не подтверждается. Тестовые окна удерживают экран включённым, а Compose-тесты ожидают появления первого корня интерфейса.

Обычный QA-запуск и instrumentation имеют раздельные Room/DataStore; старая установка использует третий независимый пакет/каталог. После тестов QA можно открыть как обычное приложение. Не запускайте две тяжёлые сборки одновременно и не перезаписывайте APK до завершения проверки обновления: скрипт повторно устанавливает тот же артефакт.

Проверка APK без заявления о полевом GPS:

```bash
python3 tools/verify-release-apk.py --apk artifacts/FitProgress-3.1-rc1-QA.apk --output /tmp/fitprogress-apk.json
```

Обе поставляемые сборки подписаны debug-ключом. Это не release-подпись. Подробный текущий результат: [RELEASE-3.1-RC1](docs/RELEASE-3.1-RC1.md).
