## JVM-тесты

```bash
./tools/run-domain-tests.sh
# На обычной машине:
./gradlew testDebugUnitTest
```

Доступный скрипт использует Kotlin compiler из Android Studio, JUnit 4.13.2, Hamcrest из IDE и Gson из локального кэша. Переменные `KOTLIN_COMPILER`, `JUNIT_JAR`, `HAMCREST_JAR`, `GSON_JAR` позволяют указать другие локальные пути. Это самостоятельный JVM-прогон, не успешная Gradle-задача.

Проверяются:

- Модели и валидация упражнений/подходов, отдельные веса/повторения/дистанция/RPE/RIR.
- Объём только фактически выполненных подходов; дублирование без результатов и с новыми ID.
- Даты и копирование недель; 10 000 исходных тренировок; все 35 готовых расписаний.
- Haversine, темп, скорость, шум/скачки/устаревшие GPS-точки, паузы, разрыв сигнала, текущий темп, отрезки 100 м и лучшие дистанции.
- Правила рекомендаций: боль/усталость/восстановление, выполнение, независимый preview; нейтральный preview не меняет временные/обычные подходы.
- Монотонное время при переводе системных часов, checkpoints без двойного счёта, паузы, остатки таймеров, другой boot и импорт без чужих anchors.
- Повторное завершение подхода, замена только невыполненного, копирование прошлого результата, добавление/перестановка во время занятия.
- Программы 1–52 недели: расписание, сдвиг, copy, разгрузка без повторного уменьшения, повторное применение без дублей, защита active/done/past и конфликтов ID.
- Ручная дорожка: отсутствие GPS-точек и GPS-рекордов, запрет будущих/некорректных данных.
- JSON v1/v2, неизвестная версия, checksum, дубликаты ID и CSV escaping/formula protection.

## Android compilation и APK в ограниченной среде

```bash
python3 tools/offline-android-build.py --android-tests --package
python3 tools/verify-apk.py  # подпись, alignment, классы, соответствие исходникам
```

Требует intermediates прошлой Gradle-сборки. Компилирует исходники, Java DAO, тесты, DEX и ресурсы, подписывает/проверяет APK, записывает source fingerprints. **Не запускает Android-тесты и Lint.** Не регенерирует Room через KAPT, не проверяет dependency resolution/clean build. Схема v1 сохранена; новые модели хранятся в прежних JSON-колонках. При изменении SQL-схемы, зависимостей или ресурсов нужен обычный Gradle build.

## Обязательный следующий Android-прогон

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
./gradlew connectedDebugAndroidTest
```

Минимум устройства/эмуляторы API 29 и API 35; GPS/батарею проверять на физическом телефоне. Тесты записывают свои данные: используйте тестовый профиль/эмулятор, предварительно экспортируйте реальную историю. `MainFlowTest` очищает пользовательскую базу приложения перед каждым сценарием.

### Smoke-сценарии

1. **Установка и обновление v1**: создать историю в 1.0, экспортировать, обновить `-r` с той же подписью; убедиться, что имя, подходы и маршруты сохранены. Не решать ошибку обновления удалением базы.
2. **Пустая база**: нет фиктивных рекордов/дистанции; создать упражнение, изменить имя, создать тренировку из нескольких упражнений, задать фактические подходы, отдых и заметки, завершить, открыть историю.
3. **Таймеры**: запустить 60 сек отдыха и временной этап; пауза/продолжение; свернуть, повернуть, уничтожить Activity, заблокировать экран. Проверить звук/вибрацию и настройки off. Во время счёта изменить wall clock: длительность не должна прыгнуть. После reboot активная сессия должна восстановиться на паузе с последнего checkpoint, а не засчитать время выключенного устройства.
4. **Редактирование занятия**: добавить подход во время занятия, переместить упражнение, заменить невыполненное. Выполненное не удаляется/не заменяется. Двойное подтверждение не меняет результат/срок отдыха.
5. **Программы**: создать 4 недели с разными днями, скопировать неделю, уменьшить нагрузку, перенести день, сдвинуть старт. Применить preview дважды: число слотов стабильно. Завершить одно занятие и изменить будущий план: история остаётся прежней.
6. **GPS**: точное/приблизительное/отказ; выключенная геолокация; GMS отсутствует; реальное движение; 15+ минут lock screen; ручная пауза с перемещением; потеря сигнала; offline с включённой геолокацией. Демо не доказательство GPS.
7. **Дорожка**: ввести км/мин/дату. В истории явная пометка, нет маршрута/GPS-рекорда; отдельно видны GPS/ручные километры.
8. **JSON/CSV**: экспорт через SAF; импорт на другом тестовом устройстве; повторный импорт без дублей; повреждённый JSON/контрольная сумма/неизвестная версия отклоняются. Программы и фактические подходы восстановлены. Изображение с чужим URI показывает fallback.
9. **Малый экран и font scale 1.5–2.0**: формы с клавиатурой, длинные названия, диалоги, нижняя навигация, экран тренировки; проверить прокрутку и доступность кнопок.
10. **Большая база**: несколько тысяч тренировок/несколько длинных маршрутов, длительное пролистывание, календарь и аналитика; профилировать память/CPU. Unit-набор не доказывает Android performance.

## Известные границы проверок

- Без устройства невозможно подтвердить OEM-ограничения батареи, поведение FGS/уведомлений, звуки, wake lock и погрешность GNSS.
- Контролируемые unit timestamps не заменяют реальный reboot/force stop.
- Room identity hash v1 не менялся, destructive fallback отсутствует. Тест legacy payload добавлен, но на Android не исполнялся; не заявляется пройденная Room migration.
- Есть compiler deprecation warnings для существующей DirectionsRun и старого доступа к Vibrator на поддерживаемых API. Это не результаты Android Lint.
