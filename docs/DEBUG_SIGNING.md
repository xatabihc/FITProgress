# Постоянная подпись тестовых APK

Android разрешает обновление поверх установленного приложения только при совпадении **applicationId** и сертификата подписи. Облачный debug APK, собранный с автоматически создаваемым ключом GitHub runner, может быть подписан иначе, чем уже установленный APK.

В GitHub Actions поддержан необязательный секрет `FITPROGRESS_DEBUG_KEYSTORE_BASE64`. Он используется **только при push в main**, а для PR не раскрывается. При отсутствии секрета обычная проверочная сборка продолжается, но такой APK **не следует** устанавливать поверх версии с важной историей без проверки сертификата.

## Однократная настройка с Ubuntu

1. Убедитесь, что локальный `~/.android/debug.keystore` — **тот самый ключ**, которым подписан APK на телефоне. Простой факт наличия файла этого не гарантирует. Если подписи различаются, **не меняйте и не удаляйте** существующее приложение. Сначала экспортируйте резервную копию.
2. Авторизуйтесь в GitHub CLI через `gh auth login`, если это ещё не сделано.
3. В обычном терминале Ubuntu выполните:

```bash
test -s "$HOME/.android/debug.keystore" || { echo 'Локальный debug.keystore не найден'; exit 1; }
base64 -w0 "$HOME/.android/debug.keystore" | gh secret set FITPROGRESS_DEBUG_KEYSTORE_BASE64 --repo xatabihc/train
```

Команда передаёт содержимое ключа в зашифрованное хранилище GitHub Secrets через stdin, не печатая ключ и не добавляя его в Git. **Не публикуйте Base64, файл keystore, пароли или ключи в чате, issues, PR либо репозитории.** Base64 не является шифрованием.

4. Проверьте только имя секрета: `gh secret list --repo xatabihc/train`.
5. После следующей сборки ветки `main` в шагах GitHub Actions найдите `Restore stable debug signing key on main` и `Verify and print debug APK signing certificate`. Сравните SHA-256 сертификата с проверенным APK, которым подписана установленная версия.

**Важно:** секрет имеет смысл только при совпадении исходного ключа. Если установленная версия подписана другим сертификатом, конфигурация GitHub не сможет обновить её без удаления приложения. Сначала сохраните данные и выясните подпись. Эту debug-подпись нельзя считать подходящей для публичного production-релиза.

Ветки PR собираются отдельным временным debug-ключом: их APK предназначены для CI-проверок и не гарантируют обновление поверх приложения с важными данными.
