# FitProgress 3.1-rc2 — итог объединения и проверки

**versionCode 8**, package `ru.fitprogress.ai`, minSdk 29 / targetSdk 35, Room v2. Это кандидат в релиз; полевой GPS и полный русский дополнительный каталог остаются открытыми.

RC2 объединяет локальный цикл стабилизации [RC1](RELEASE-3.1-RC1.md) и актуальный на момент fetch `origin/main` (`ebbfcc7`). История Git не переписывалась. Новые изменения GitHub сохранены: дополнительные русские названия/инструкции, нормализация фильтров, семь программ с прогрессией и разгрузкой, недельный обзор, системный GPS fallback, актуальность GPS-индикаторов, выбор точек карты и создание отсутствующих упражнений при импорте программ.

Локальные исправления сохранены: возврат домой с сохранением состояния вкладок, открытие результата и повторного экрана бега, разрыв GPS после 20 секунд без начисления соединяющего расстояния, действие продолжения через foreground PendingIntent, ограниченное чтение внешних файлов, независимое копирование программы, ленивые каталоги выбора упражнений, согласованная палитра, крупный шрифт, импорт внешней истории с предпросмотром/сопоставлением/дедупликацией. Дополнительно исправлены сообщение при достижении восьми промежуточных точек и ввод круговой дистанции с десятичной запятой.

## Проверено

- **170 JVM tests passed**; отдельный `tools/run-domain-tests.sh` и Gradle.
- **40 Android methods passed, 0 failed, 2 assumption skips** на Samsung SM-A075F (`OK (42 tests)`). В общем suite по условию пропущены opt-in физический GPS lifecycle и host-controlled persistence. Оба сценария выполнены отдельно: GPS lifecycle — успешно; persistence фазами seed / install-r / verify — успешно.
- В числе проверенных сценариев: навигация и повторный возврат домой, создание/редактирование упражнения, силовая с выполненным подходом и пересозданием Activity, программа/календарь, две последовательные симуляции перехода записи бега в сохранённый результат без вымышленных GPS-точек, импорт/повторный импорт/транзакция, Room reopen/upgrade, каталог и поиск, поворот, 2× шрифт в обеих темах. При фактически выключенном GPS проверен отказ настоящего сервиса без изменения истории.
- APK QA установлен повторным обновлением без очистки; приватная обычная QA-база и изолированная тестовая база разделены.
- Метаданные, CRC, подпись, 16-KB ZIP alignment, arm64 и наличие нужных DEX/Room проверяются `tools/verify-release-apk.py`. У телефона страница памяти 4096 байт; ZIP alignment не подменяет отдельную проверку ELF на 16-KB устройстве.
- Первоначальные неуспешные RC1-прогоны сохранены, не объявлены успешными. Текущий RC2 имеет отдельные отчёты в `verification/v3.1-rc2/`.

## Подпись и перенесённые данные

Локальный ключ `2a8cc13c…` отличается от сертификата старой установленной версии `a0d1b995…`. Последний предыдущий CI APK (run 41681645275) совпадал с установленным сертификатом, однако **новый RC2 CI run 42224713180 получил другой сертификат `3ecfba7b…`**. Стабильность CI-подписи не подтверждена. Защита `tools/verify-compatible-update.py` отклонила обычное обновление **до install-r**; старый FitProgress 3.0-dev (код 6) не изменён и не удалён. Ключи не скачивались, не заменялись и не публиковались.

Проверено, что обычная QA-база не содержала ни одной пользовательской строки. Она сохранена для отката, затем в **FitProgress QA 3.1** перенесена вся совместимая Room v2 история из старой установки штатным `run-as` без root. Непустые целевые базы скрипт переносом не заменяет. Приватный исходный SQLite-снимок и резервная пустая QA-база находятся в игнорируемом `qa-reports/private-history-snapshot/` (0700/0600). Проверены целостность, Room identity и совпадение всех столбцов всех строк четырёх пользовательских таблиц после запуска интерфейса. Профиль DataStore также перенесён, поскольку в QA не было пользовательских настроек; оригинальный профиль не изменялся.

Android SELinux запретил создание hard link при первом переносе; операция завершена переименованием с `mv -n`, без перезаписи. До этого пустая QA-база была сохранена отдельно. История старой установки во всех этапах оставалась неизменной. Права чтения внешних изображений привязаны к package ID и не переносились: при недоступном фото показывается локальная иллюстрация.

Снимки обычных пользовательских экранов и личные записи не публикуются. Проверка вкладок после переноса проводится визуально, поскольку системная accessibility-иерархия при текущей накладке не отдаёт ожидаемые подписи; это не подменяет полный автоматический Compose suite на отдельном хранилище.

Для дальнейших тренировок запускайте **FitProgress QA 3.1** с версией **3.1 RC2** в верхней строке. Старый FitProgress оставлен резервной отдельной установкой; новые записи между двумя пакетами автоматически не синхронизируются. Повторная установка QA APK использует тот же сохранённый локальный ключ и `adb install -r`; очистка не требуется.

## Ограничения

- Реальный маршрут на улице, точность/батарея и длительный Samsung lock-screen/Doze не проверены; GPS телефона исходно выключен; для отдельного сервисного теста он кратко включался, затем исходное выключенное состояние восстановлено и проверено.
- Нет реального файла экспорта «Рубеж12». Поддерживаемая схема внешнего JSON и отсутствие угадывания дат/статусов описаны в [RC1](RELEASE-3.1-RC1.md); совместимость с конкретным экспортом не подтверждена.
- Дополнительный открытый каталог переведён частично. Полной русификации всех названий и инструкций нет.
- Карты и дорожная маршрутизация зависят от доступности OSM/Valhalla/Nominatim; полноценной offline-карты и offline routing нет. Условия OSM: https://operations.osmfoundation.org/policies/tiles/; массовая предзагрузка не используется.
- Нет полного визуального перебора всех диалогов/клавиатур и длительного стресс-прогона. Оба варианта APK — debug, не production release.

Чистая стандартная сборка RC2: **BUILD SUCCESSFUL**, 84 задачи выполнены. Lint: **0 ошибок, 61 предупреждение, 1 информационное замечание**; все предупреждения сохранены в итоговой разбивке `verification/v3.1-rc2/checks.json`.

## Последняя доработка каталога

Подготовка нормализованного поискового индекса названий, псевдонимов и полных инструкций вынесена из композиции CatalogScreen в кешируемый поток ViewModel на Dispatchers.Default. Это устраняет тяжёлую синхронную работу при первом нажатии вкладки. Отдельный Android-тест проверяет, что фоновый индекс получает созданное и переименованное упражнение и не оставляет старое название. Число UI-тестов и хеши ниже относятся к последней пересборке после этой правки.

## GPS, статистика и окончательный артефакт

Настоящий Android foreground service отдельно прошёл старт, отсчёт времени, паузу, продолжение и завершение на Samsung. Геолокация временно включена для теста и восстановлена в исходное состояние false в finally; разрешения обычного старого приложения не менялись. Тест использует только изолированное QA-хранилище. Mock provider не применялся, координаты в отчёт не включены. Это не проверка реальной прогулки, точности маршрута, заблокированного экрана или Doze. Отчёт: `verification/v3.1-rc2/gps-lifecycle/summary.json`.

Добавлен режим статистики «День». Android-тест создаёт две завершённые тренировки (сегодня/вчера) в изолированной Room и проверяет, что дневной счётчик содержит только сегодняшнюю. Реальные пользовательские данные фикстурами не изменяются.

Основной APK для телефона: **`artifacts/FitProgress-3.1-rc2-QA.apk`**. Он подписан существующим сохранённым локальным debug-ключом и устанавливается поверх QA без очистки. Сверяйте `artifacts/SHA256SUMS` и `verification/v3.1-rc2/apk-qa.json`; промежуточные локальные/CI APK предназначены для диагностики и не подходят для обновления старого package ID. Последняя установка QA после переноса истории также проверена сравнением всех пользовательских строк с исходным снимком; профиль перенесён, исходные данные не менялись. Открытие всех пяти основных вкладок просмотрено визуально, при этом серийный benchmark времени отклика не проводился.

На телефоне запускайте **FitProgress QA 3.1**. Для записи на улице включите геолокацию в настройках телефона; после тестов она оставлена в исходном выключенном состоянии. Старый FitProgress не удалён и остаётся отдельной резервной установкой. Это **debug-кандидат**, не production release и не утверждение о выполнении всех критериев исходного задания.
