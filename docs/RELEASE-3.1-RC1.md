# FitProgress 3.1-rc1 — аудит и проверка

Версия 7, minSdk 29, targetSdk 35. Кандидат для проверки, не подтверждённый полевой релиз. Схема Room остаётся v2; destructive migration не добавлялась.

## Импорт пользовательского JSON

Настройки → «Импорт из Рубеж12 / другого JSON». Используется только файл, выбранный системным Android picker. Реального экспорта «Рубеж12» в проекте нет: совместимость с его конкретной версией не подтверждена. Импортер поддерживает явно описанную структуру; несовместимые записи показывает в отчёте, не выдаёт их за перенесённые.

Поддерживаются корневой массив либо объект с массивом `workouts`, `trainings`, `trainingSessions`, `тренировки`. Пример:

```json
{"workouts":[{"id":"source-workout-42","name":"Силовая","date":"2026-11-04","status":"completed","durationMs":1800000,"exercises":[{"name":"Отжимания","restSeconds":60,"sets":[{"reps":12,"weight":0,"done":true}]}]}]}
```

Статусы: `completed/done/finished`, `active/paused/in_progress`, `planned/scheduled/pending`; доступны основные русские соответствия. Дата обязательна; поддерживаются ISO date и ISO instant с Z. Единицы: кг, секунды для подхода, метры, миллисекунды для длительности тренировки. Числа с запятой допустимы как JSON-строки. Отсутствующие числовые значения показываются нулями с пояснением; без явной отметки `done/completed` подход не включается в выполненный объём. Неизвестные даты и статусы не угадываются.

Предпросмотр позволяет заменить соответствие упражнению из каталога. Неизвестное название сохраняется как пользовательское упражнение. Незавершённые занятия становятся черновиками с сохранением фактических подходов: одновременно активной может быть только одна тренировка. Повторный ID пропускается; существующие результаты не перезаписываются. При отсутствии исходного ID используется устойчивый отпечаток содержимого. Импорт ограничен 20 МБ / 20 000 тренировок; программы и GPX — 10 МБ.

## Подпись и безопасная установка

На подключённом Samsung SM-A075F сертификат существующего `ru.fitprogress.ai` отличается от доступного debug-ключа. Совместимого ключа в доступных файлах не найдено. Обычный APK нельзя установить поверх этой установки. Приложение и данные телефона не удалялись.

`-PfitQa=true` собирает отдельный `ru.fitprogress.ai.qa` с названием «FitProgress QA 3.1». Он устанавливается рядом с существующим приложением. Инструментальные тесты используют FitTestApplication с отдельными Room/DataStore. Обычный запуск QA использует собственное локальное хранилище, отдельное от старого приложения и тестовых данных. Чтобы перенести историю вручную, экспортируйте резервную копию в старом FitProgress и импортируйте её в новой установке. Не удаляйте старую установку до проверки копии.

Ключи не создавались заново, не заменялись и не включаются в Git. Для настоящего обновления `ru.fitprogress.ai` нужен оригинальный ключ подписи; debug APK не является release APK.

## Карты

MapLibre + стандартные OSM tiles, без платного API-ключа. Атрибуция и идентифицирующий User-Agent сохранены. HTTP-кэш ограничен, массовая предзагрузка отсутствует. Условия: https://operations.osmfoundation.org/policies/tiles/ (проверено 2026-11-06). Тайлы и маршрутизация требуют сети/доступного провайдера; офлайн сохраняются GPS, результаты и схема трека, но не полноценная автономная карта. Valhalla/Nominatim — внешние best-effort сервисы без гарантии доступности.

## Открытые ограничения

- Реальные координаты на прогулке/пробежке, длительный lock screen/Doze и энергосбережение Samsung не проверены. GPS телефона исходно выключен; глобальные настройки не переключались.
- Нет исходного пользовательского экспорта «Рубеж12» для подтверждения конкретного формата.
- Большая часть открытого дополнительного каталога по-прежнему имеет английские оригинальные названия/инструкции. Полная русификация всего каталога не достигнута. Базовые упражнения и основной интерфейс русские.
- Полнота визуального обхода каждого диалога/всех вариантов клавиатуры, длительный стресс, физическая точность GPS и полноценная offline routing не подтверждены.
- Подпись старой установки недоступна; проверка повторного обновления QA не доказывает совместимость обновления старого приложения.
- Lint warnings и результаты текущего прогона приведены в итоговом разделе; отсутствие lint errors не доказывает отсутствие всех дефектов.

## Воспроизведение проверок

```bash
./gradlew --no-daemon --max-workers=2 -PfitQa=true testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
python3 tools/verify-device-qa.py --serial SERIAL --output /tmp/fitprogress-qa
./gradlew --no-daemon --max-workers=2 clean testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Первый первоначальный device suite: 36 методов, 5 падений; второй: 38 методов, 13 падений из-за отсутствовавшего Compose-окна; третий: 38 методов, 1 падение из-за отсутствия прокрутки к полю имени. Эти результаты сохранены отдельно в `docs/verification/v3.1-rc1/device-initial`, `device-second`, `device-third`; они не объявляются успешными. Ожидание появления Compose-root ограничено 15 секундами. TestApplication удерживает экран включённым только во время тестовых Activity; глобальные настройки телефона не менялись.

## Итог текущего цикла

- Чистая стандартная сборка: `clean testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest` — **BUILD SUCCESSFUL**, 84 задачи выполнены. Лог: `verification/v3.1-rc1/gradle-clean-standard.txt`.
- JVM: **158 / 158**, ошибок и пропусков нет. Покрываются расчёты GPS/разрывы/паузы, таймеры, календарные планы, статистика и цели, миграция SQL на длинной истории, импорт, копирование, последовательность записей.
- Lint: **0 errors, 59 warnings**. Разбивка по категориям в `verification/v3.1-rc1/checks.json`. Предупреждения не скрывались: среди них обновления зависимостей, использование Log вместо Timber, неиспользуемые ресурсы и рекомендации по KSP/backup rules.
- На реальном **Samsung SM-A075F**: полный suite — **36 passed, 0 failed, 2 assumption skips** (`OK (38 tests)`). Отдельно прошли **seed / повторный install-r / verify** контрольной истории с одним выполненным подходом и неизменным объёмом. Эти две фазы не входят в 36 методов основного успешного прогона.
- Пропуски: аппаратная запись GPS с opt-in не запускалась; persistence-метод основного suite требует host-controlled phase и затем выполнен отдельно. При реально выключенном GPS отдельный DisabledGpsTest прошёл и подтвердил отказ без изменения истории.
- Проверены создание/редактирование упражнения, начало/выполненный подход/сохранение силовой, программа и календарь, возврат домой, два последовательных открытия результата пробежки через реальные состояния UI без фиктивных GPS-точек, Room reopen/upgrade, импорт и дедупликация, каталог/поиск, поворот/возврат и 2× шрифт в двух темах. Это не полный визуальный перебор каждого состояния приложения.
- Обычный запуск установленного QA вне instrumentation: `Status: ok`, холодный запуск Activity **1876 мс** в одной выборке; бренд главной виден, диалога ошибки чтения нет. Это не серия измерений производительности и не стресс-тест.
- APK обоих пакетов прошли проверку `apksigner`, CRC ZIP, `zipalign -P 16`, метаданных, arm64 и присутствия Room v2/классов. 16-KB zip alignment не выдаётся за отдельную полевую проверку ELF на 16-KB устройстве; у Samsung фактическая страница памяти 4096 байт.
- Снимок каталога из изолированных фикстур: `verification/v3.1-rc1/catalog-device.png`; просмотрен визуально. Пользовательские экраны и текст из обычного хранилища в Git не включались.

Снимок лежит в игнорируемом `qa-reports/private-history-snapshot/` с правами каталога 0700 / файла 0600. Автоматическое копирование в QA **не выполнено**: целевой файл базы уже существует, сработала защита от перезаписи. Оригинальная база не менялась.
