## Обнаруженные проблемы и исправления

| Находка | Исправление |
|---|---|
| GPS интервалы/темп и freshness зависели от wall clock | Новые точки содержат elapsed time/boot; вычисления используют монотонное время, старые маршруты совместимы |
| Неподвижность могла считаться потерей GPS, поскольку freshness обновлялась только по принятой дистанции | Свежесть отслеживается и для точных стационарных измерений, шум не добавляет дистанцию |
| Нет оценки точности/mock provider мог попасть в реальный трек | Явный отказ, без добавления фиктивного километража |
| Разрешение/провайдер могли отключиться без новых callbacks | Проверка в checkpoints, пауза с явным статусом |
| Wake lock истекал через фиксированное время | Обновление до expiry, освобождение при паузе/завершении |
| Настройки сохранялись полной устаревшей копией Profile | Атомарный read/modify/write DataStore |
| Нельзя было хранить цели/дневник отдельно | Room v2 с явной additive migration и отдельной таблицей |
| Restore формы до загрузки Room мог открыть пустые оценки вместо существующей записи | Согласованный PersonalState.loaded; редактирование доступно после загрузки |
| Coach не учитывал актуальную боль, двухнедельную базу и скачок бега | Новые структурированные safety gates, revalidation в транзакции |
| Повтор упражнения в разные дни мог использовать чужой фактический результат | Preview строится из собственного исходного занятия/дня |
| Повтор фактической недели использовал плановую дату | Для repeat берётся дата реального завершения |
| Восстановление выбирало «последнюю строку», а не последнюю дату | Хронологическая сортировка источника |
| Округление маленьких весов могло превысить заявленный прирост | Округление вниз, исходный минимум, cap модели |
| Разминка могла ошибочно закрыть цель рабочего веса | Разминочные подходы исключены из этой цели |
| Активный demo/manual в импортируемой копии мог стать скрытым незавершаемым занятием | Такие состояния отклоняются при валидации |
| Старые UI-тесты очищали обычную базу перед сценарием | Новый FitTestRunner/TestApplication используют отдельные БД/DataStore, перед очисткой проверяется изоляция. Старый test APK архивирован без удаления |
| Экспорт мог записать файл, не проходящий собственные ограничения импорта | Checked export до открытия output stream, сериализация вынесена с main |
| Недельный редактор требовал прокручивать до 52 chips | Прямой переход по номеру, повтор недели до конца, полное удаление/порядок подходов/упражнений |

## Сохранность данных

SQL миграции находится в `SchemaMigrations.kt`; Android Migration вызывает именно эту константу. JDBC-тест создаёт прежние таблицы по schema v1, записывает 10 000 UTF-8 payload и записи упражнений/бега, выполняет SQL, сравнивает все старые значения побайтно. Старые entity schema v1/v2 также сравниваются. Новая таблица пуста; destructive SQL отсутствует. Room Java/schema v2 сгенерированы официальным RoomProcessor, не написаны вручную.

Дополнительно добавлен Android-тест открытия файла v1 через Room v2, чтения старого payload и записи цели/дневника. Тест сохранения старых DataStore-ключей/атомарных обновлений и additive import также добавлен. **Эти Android-тесты только скомпилированы, не выполнены.** Наличие SQL-теста не доказывает успешную установку/обновление APK на физическом телефоне.

Подпись нового APK сравнивается с исходной 2.0-dev; applicationId сохранён, versionCode увеличен до 3. Установка `-r` и данные реального пользователя ещё требуют smoke-теста. APK старой версии не следует открывать поверх базы v2.

## Границы аудита

Не проверены физический GPS, OEM battery management, звук/вибрация, lock screen/reboot, small-screen rendering/TalkBack, Room lifecycle на Android, профили памяти/CPU и clean Gradle/Lint. Нет заявления о стабильном релизе или индивидуальной медицинской безопасности. Алгоритм Coach объяснимый и локальный, комментарии свободным текстом не анализирует.
